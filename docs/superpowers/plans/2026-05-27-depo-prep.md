# Depo Prep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a "Depo Prep" wizard task that generates a topic-organized deposition outline from user-curated sources, in two subprocess phases (analyze → user-curates-topics → generate).

**Architecture:** Two-phase subprocess agent (`Scripts/depo_prep.py`) following the `summarize_deposition.py` AWAITING_INPUT handoff pattern. Phase 1 = per-source structured digest (Flash, parallel) + topic clustering (Pro). Lawyer edits topics in the Settings page. Phase 2 = per-topic question fan-out (Pro, parallel) → dedup → polish → render docx+md. Custom Settings page (extends `SettingsPage`) and custom Output page (extends `OutputPage`).

**Tech Stack:** Python 3.x, PySide6 (QStackedWidget, QListWidget with native drag), `LLMCaller` (Gemini Pro/Flash with Claude/OpenAI fallback), `python-docx`, `concurrent.futures.ThreadPoolExecutor`, `pytest` + `pytest-qt`, mocked LLM at the `LLMCaller.call` boundary.

**Spec:** [docs/superpowers/specs/2026-05-27-depo-prep-wizard-task-design.md](../specs/2026-05-27-depo-prep-wizard-task-design.md) (commit `2426771`).

### Cross-cutting rules every task must follow

1. **Windows subprocess encoding** — any `subprocess.run` / `Popen` that handles document text MUST pass `encoding="utf-8", errors="replace"`. ([MEMORY.md `windows_subprocess_text_encoding.md`])
2. **Agent script sys.path** — `Scripts/depo_prep.py` MUST `sys.path.insert(0, project_root)` BEFORE importing from `icharlotte_core` (see top of `Scripts/summarize_deposition.py`).
3. **Worktree vs main checkout** — iCharlotte runs from `C:\geminiterminal2\`, NOT the worktree. After implementation, the user will rebase/copy to main. Do not modify `C:\geminiterminal2\` directly from the worktree session.
4. **No hardcoded tab indices** in any `iCharlotte.py` edit; use `_index_of_tab(name)`.
5. **QListWidget drag-reorder** — use native `Qt.ItemFlag` flags, never `setItemWidget` (breaks drag).
6. **Word output** — never empty paragraphs for spacing (use `space_after`); never touch `\r`; validate produced .docx via `icharlotte_core/word_validator.validate_after_edit`.
7. **python-docx tables** — use `icharlotte_core.document_processor.extract_docx_text` for .docx extraction (it walks the body in order and handles tables); never `for p in doc.paragraphs`.
8. **TDD discipline** — every task writes the test first, runs it red, then implements, then runs it green, then commits.
